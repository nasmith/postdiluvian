# Postdiluvian

A small, self-contained browser for a cocktail collection. One HTML file, one JSON
file, no build step, no framework. Runs as a static site on GitHub Pages.

**Live:** https://nasmith.github.io/postdiluvian/ *(after Pages is enabled)*

The public site ships **six classics** (Martini, Negroni, Manhattan, Whiskey Sour,
Daiquiri, Sidecar). The full collection is kept privately and shared as a file —
open the site and use **“Load a collection file…”** (or drag the file onto the page).
A loaded collection is remembered in that browser until you hit “Reset to public.”

## Layout

Two repos, side by side:

```
postdiluvian/                 (this repo — public)
  index.html                  the app. Vanilla JS; fetches data/collection.json.
  editor.html                 browser editor for the private masters (see below)
  style.css                   design tokens shared by index.html + editor.html
  data/collection.json         COMMITTED, generated. The six public basics,
                               self-contained ({ meta, ingredients, cocktails }).
  tools/publish.py             private masters -> data/collection.json + the full file
  tools/validate.py            integrity check for a collection file. Runs in CI.
  bin/save                     commit the site + back up the private repo in one step
  schema/collection.schema.json
  .githooks/pre-commit         runs publish.py + validate.py, re-stages data/collection.json
  .github/workflows/           data validation + Pages deploy

postdiluvian-private/          (sibling — PRIVATE repo; never referenced by this one)
  cocktails.json               full recipe list — the master you hand-edit
  ingredients.json             full ingredient vocabulary — the master you hand-edit
  collection.full.json         generated by publish.py — the file you share privately
  build.py                     one-shot CSV migration, kept as provenance
  source/, DECISIONS.md
```

`publish.py` looks for the private repo at `../postdiluvian-private`, or wherever
`$POSTDILUVIAN_PRIVATE` points. If it's not there (a bare clone of this repo),
publish and the hook no-op and the committed `data/collection.json` stands.

## Working on it

```bash
git config core.hooksPath .githooks     # once per clone, so the pre-commit hook runs
python3 -m http.server 4173             # then open http://localhost:4173
```

Edit `../postdiluvian-private/cocktails.json` (recipes) and `ingredients.json`
(vocabulary). Then:

```bash
bin/save "added the Jungle Bird"
```

That commits this repo (the hook regenerates the collection files and bumps
`meta.version` — calendar `2026.09.05`, then `2026.09.05.2` for a second change
that day, only when content actually changed), then commits and pushes
`postdiluvian-private`.

Manual equivalent:

```bash
python3 tools/publish.py
python3 tools/validate.py ../postdiluvian-private/collection.full.json
```

## Editing in the browser — `editor.html`

An alternative to hand-editing the JSON. Open
[`editor.html`](https://nasmith.github.io/postdiluvian/editor.html), load
`cocktails.json` and `ingredients.json` from `postdiluvian-private/` (pick both,
or drag them on). Everything is in-browser; nothing uploads.

**Starting your own collection?** The load screen has a **Load the 8-classic
sample** button — it pulls
[`data/starter/cocktails.json`](data/starter/cocktails.json) +
[`data/starter/ingredients.json`](data/starter/ingredients.json) (the eight
public classics, in master-file format). Edit, **Save both**, drop the files in
a folder of your own, and point `publish.py` at it via `$POSTDILUVIAN_PRIVATE`.
Those two files are regenerated by `publish.py` alongside `data/collection.json`.

- guided forms for every field — dropdowns for method/glass/etc, ingredient
  autocomplete, per-row amount modes (ml / tsp / dashes / rinse …), auto-slug ids,
  a live recipe preview, and a `</> JSON` toggle on any entry
- full add / edit / delete on both files; a `JSON` tab for editing either file raw
- real-time validation (the same checks as `tools/validate.py`) — issues list at
  the bottom, inline field markers, **Save** disabled while errors remain
- **Save both** downloads the two files (formatted exactly like the originals).
  Move them into `postdiluvian-private/`, then run `bin/save`.

### Import a recipe with an AI assistant

**Recipes ▸ Import…** builds a filled-in extraction prompt (the schema, the
amount rules, and your current ingredient vocabulary) from a URL *or* pasted
recipe text. You run that prompt wherever you already have an assistant —
[claude.ai](https://claude.ai), ChatGPT, etc. — and paste its JSON reply back.
The editor turns it into a new recipe, adds any new ingredients, and drops it
into the normal form with an **imported / review** banner; validation runs as
usual; **Discard import** undoes the whole thing.

**No API key, no account setup, nothing leaves the page** — the editor only
builds the prompt and parses what you paste back. (If a one-click version that
calls an API directly is ever added, its key would live only in that browser's
`localStorage` for this origin — never in a file, never in the repo. Use a
dedicated key with a spend cap and keep it out of git.)

## Collection file format

Anything the app loads — public or private — is one JSON object:

```jsonc
{
  "meta": { "kind": "postdiluvian-collection", "name": "…", "version": "2026.09.05" },
  "ingredients": [ /* every ingredient any recipe below references */ ],
  "cocktails":   [ /* the recipes */ ]
}
```

### cocktail

```jsonc
{
  "id": "negroni", "name": "Negroni", "aka": [], "variantOf": null, "status": "active",
  "base": ["gin"],                 // ingredient ids — drives the spirit filter
  "method": "stir",                // shake | dry-shake | stir | build | swizzle | blend | throw
  "glass": "old-fashioned",        // coupe | old-fashioned | rocks | nick-and-nora | flute | collins | highball
  "service": "rocks",              // up | rocks | long | neat
  "ice": "large-cube",             // none | large-cube | cubed | crushed
  "garnish": "Orange twist",
  "tags": ["bitter", "aperitivo", "spirit-forward", "stirred"],
  "notes": "",
  "source": { "book": "", "author": "", "url": "", "page": null, "note": "" },
  "ingredients": [
    { "ref": "gin", "ml": 30, "brand": "Tanqueray" },
    { "ref": "campari", "ml": 30 },
    { "ref": "angostura-bitters", "amount": 2, "unit": "dash" },
    { "ref": "absinthe", "unit": "rinse" }
  ],
  "steps": ["Stir with ice.", "Strain over one large cube.", "Garnish with an orange twist."]
}
```

An ingredient entry carries **`ml`** (number — canonical amount, converted to oz and
scaled for batches), **or** `amount` + `unit` for counts (`dash`, `drops`, `tsp`,
`barspoon`, `piece`), **or** just `unit` for `rinse` / `top`. Extras: `"approx": "max"`,
`"note"` (prep, or "or Cointreau"), `"brand"`.

### ingredient

```jsonc
{
  "id": "green-chartreuse", "name": "Green Chartreuse",
  "category": "liqueur",   // spirit | vermouth | fortified | wine | liqueur | amaro | bitters | juice | syrup | other
  "family": null,          // spirits only: gin | whiskey | rum | agave | brandy | vodka | aquavit | other
  "aliases": ["chartreuse"], "brands": ["Chartreuse"], "pantry": false
}
```

`id`s are permanent (loaded favorites/bar are keyed to them); names are free to change.

## Deploying

Settings → Pages → Source: **GitHub Actions**. `.github/workflows/pages.yml`
publishes the repo root on every push to `main`.
